# ABS Inventory & Procurement Assistant API

REST API для складского учёта и расчёта потребности в закупке. Сервис рассчитывает остатки из движений, списывает товар по FEFO, строит прогноз закупки и показывает складские риски.

## Возможности

- регистрация и просмотр движений товара;
- текущие остатки по объектам и партиям;
- средний расход за 90 дней и запас в днях;
- FEFO-распределение расхода по партиям;
- прогноз спроса и рекомендуемого объёма закупки;
- учёт поставок в пути, срока поставки, размера упаковки и минимальной партии;
- предупреждения о дефиците, сроках годности и отсутствии движения.

После запуска документация API доступна по адресу <http://localhost:8000/docs>.

## Быстрый запуск через Docker

Нужны Docker и Docker Compose.

```bash
docker compose up --build
```

Команда запускает PostgreSQL и API, применяет миграции Alembic и загружает демонстрационные данные. PostgreSQL доступен только внутри Docker-сети, поэтому он не конфликтует с локальной установкой на порту 5432.

Проверка:

```bash
curl http://localhost:8000/api/stock
curl http://localhost:8000/api/alerts
```

Остановка:

```bash
docker compose down
```

Удаление контейнеров вместе с демонстрационной базой:

```bash
docker compose down -v
```

## Локальный запуск

Нужны Python 3.11 и PostgreSQL.

1. Создайте базу данных PostgreSQL.
2. Создайте виртуальное окружение и установите зависимости:

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements-dev.txt
```

Для Linux и macOS команда активации: `source venv/bin/activate`.

3. Скопируйте `.env.example` в `.env` и укажите строку подключения.
4. Примените миграции и при необходимости загрузите демонстрационные данные:

```bash
alembic upgrade head
python -m scripts.seed
```

5. Запустите API:

```bash
uvicorn main:app --reload
```

Скрипт стартовых данных идемпотентен: повторный запуск не создаёт дубли.

## Тесты и проверки

Перед интеграционными тестами база должна существовать, а миграции должны быть применены. Тесты выполняются в транзакциях и откатывают созданные данные.

```bash
pytest -q
ruff check . --exclude venv --ignore FURB157,B008,DTZ011
```

Для запуска тестов внутри работающего Docker-контейнера сначала установите зависимости из `requirements-dev.txt` либо используйте локальное виртуальное окружение.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/movements` | Зарегистрировать движение и получить новый остаток |
| `GET` | `/api/movements` | Получить движения с фильтрами и пагинацией |
| `GET` | `/api/stock` | Получить сводные остатки |
| `GET` | `/api/stock/{sku}` | Получить остатки товара по объектам и партиям |
| `POST` | `/api/forecast` | Рассчитать потребность и стоимость закупки |
| `GET` | `/api/alerts` | Получить предупреждения по складу |

### Типы движений

- `receipt` — поступление;
- `consume` — расход;
- `writeoff` — списание указанной партии;
- `return` — возврат в указанную партию;
- `correction` — положительная или отрицательная корректировка указанной партии.

Расход `consume` распределяется по FEFO: сначала используется доступная партия с ближайшим сроком годности. Просроченные партии в расходе не участвуют и закрываются через `writeoff`.

## Расчёты

Остаток не хранится отдельным изменяемым полем. Он каждый раз вычисляется как сумма поступлений, возвратов и корректировок за вычетом расхода и списаний.

Средний дневной расход рассчитывается по операциям `consume` за последние 90 дней:

```text
средний расход = расход за 90 дней / 90
```

Прогноз и точка заказа:

```text
прогнозный расход = средний расход * дней в периоде
страховой запас = средний расход * страховой запас в днях
точка заказа = средний расход * срок поставки + страховой запас
потребность = прогноз + страховой запас - остаток - поставки в пути
```

Положительная потребность округляется вверх с учётом минимальной партии и кратности упаковки. Ориентировочная стоимость использует цену последнего поступления.

## Архитектура

- `api/` — HTTP-маршруты FastAPI и преобразование результата в схемы ответа;
- `services/` — сценарии работы с БД и координация расчётов;
- `calculation/` — детерминированные функции FEFO, остатка и прогноза;
- `product.py` — SQLAlchemy-модели;
- `schemas.py` — Pydantic-схемы запросов и ответов;
- `migrations/` — миграции Alembic;
- `scripts/seed.py` — демонстрационный набор данных;
- `tests/` — unit, API и интеграционные тесты.

Такое разделение позволяет тестировать формулы без HTTP и заменять способ хранения данных без переноса бизнес-логики в маршруты.

## Демонстрационные данные

После запуска доступны объект `MS-01` и товары:

- `OIL-001` — партия с приближающимся сроком годности;
- `CREAM-001` — низкий остаток и поставка в пути;
- `TOWEL-001` — позиция без недавнего движения.

Даты стартового набора вычисляются относительно дня первой загрузки, поэтому предупреждения остаются показательными при развёртывании.

## Ограничения MVP

- один пользователь, без авторизации и ролевой модели;
- горизонт в месяцах считается как 30 дней на месяц;
- средний расход не учитывает сезонность и плановую загрузку;
- заказы не размещаются автоматически;
- уведомления рассчитываются по запросу и не отправляются во внешние каналы.
